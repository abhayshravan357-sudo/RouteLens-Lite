## 1. Data Source Categories

| Category | Code | Meaning |
|---|---|---|
| REAL_HOST_DATA | A | Collected from the actual machine running the backend (`ip addr`, `ip route`, `ip neigh`, `getaddrinfo()`, `ping`, `traceroute`) |
| SIMULATED_LAB_DATA | B | Generated by RouteLens's virtual network/routing simulation (editable routing table, scenario trace, namespace lab) |
| CALCULATED_DATA | C | Computed from verified inputs using an algorithm (longest-prefix match, route analysis) — no system operation |
| MOCK_OR_FIXTURE_DATA | D | Generated for testing only (`conftest.py` hardcoded mocks; never in production responses) |
| HARDCODED_OR_UNKNOWN | E | Static values or data whose source cannot be established |

**Core principle:** A result shown to the user must carry a traceable provenance. Nothing is classified as REAL_HOST_DATA unless the backend actually executes a system operation and the result is not transformed into something it is not.

## 4. Gaps: Where Source Is Not Honestly Identified

| # | Location | Lines | Issue | Category |
|---|---|---|---|---|
| 1 | `frontend/src/types/routing.ts` | 405 | `ScenarioTrace.provenance` is hardcoded literal `'simulated'` | B presented without source flexibility |
| 2 | `frontend/src/components/ScenarioJourney.tsx` | 527 | `ProvenanceBadge provenance="simulated"` hardcoded | B always shown as simulated |
| 3 | `frontend/src/components/VirtualLabPanel.tsx` | 871-895 | Device list renders scenario-defined devices with no real status | B presented as if deployed |
| 4 | `frontend/src/components/ScenarioJourney.tsx` | 1066 | `link.is_up ?? true` from scenario definition only | Link status is B, not real |
| 5 | `frontend/src/App.tsx` | 157-170 | `loadScenarios()` fetches once, no staleness check | Data may be stale without indication |
| 6 | `backend/tests/conftest.py` | 14-49 | `mock_environment_network_if_empty` injects hardcoded MOCK_IPV4_ROUTES/etc. when real `ip` returns empty | D injected into test path (test only, not production) |

**Critical gap (#1-2):** `ScenarioTrace.provenance` is typed as the literal `'simulated'` and the UI hardcodes the badge. Even when `ComparePanel` runs a trace against a real deployed lab, the trace itself keeps the `simulated` badge. This misrepresents the data source.

**Critical gap (#6):** The test conftest mock can make report-honesty tests pass with fabricated host data marked as if it came from real commands. This does not affect production but weakens test evidence (see `testing-and-validation.md`).

## 5. Summary: What Is Real vs Simulated

| Data type | Endpoints/features | Category | Honest about source? |
|---|---|---|---|
| Host interfaces/routes/neighbors | `/network/interfaces`, `/network/routes`, `/network/neighbors`, `/network/all` | A REAL_HOST_DATA | Yes |
| DNS resolution | `/network/dns-resolve` | A REAL_HOST_DATA | Yes |
| Connectivity (ping/TCP) | `/network/connectivity` | A REAL_HOST_DATA | Yes |
| Traceroute | `/network/traceroute` | A REAL_HOST_DATA | Yes |
| Route lookup / packet journey | `/lookup`, `/packet-journey`, `/routes/analysis` (modelled) | C CALCULATED_DATA from B table | Yes (provenance fields) |
| Editable routing table | `/routes` | B SIMULATED_LAB_DATA | **Partially** — no provenance badge on table rows |
| Scenario trace / lab | `/api/scenarios/*/trace`, `/api/lab/*` | B SIMULATED_LAB_DATA | **No** — provenance hardcoded `'simulated'` |
| Health check | `/health` | C CALCULATED_DATA (static) | N/A |
| Report | `/api/report` | Mixed (A+B+C) | Yes — evidence provenance per item |

**Bottom line:** RouteLens honestly identifies the source of real host data (A) and calculated data (C). The main trust gap is in simulated data (B): scenario traces and the editable routing table are not consistently labelled with their source, and `ScenarioTrace.provenance` is hardcoded rather than dynamic.
